# 2.5.0

## Features

- `cwtools validate` can report on a subset of the mod. `--file <PATH>` (repeatable) names files directly; `--since <GIT-REF>` takes them from git, diffing the working tree against the merge base of the ref and HEAD so a branch reports what it changed rather than what its base branch did, and counting untracked files. The two union. Both scope the report, the error and warning counts, and the exit code, which is what a pre-commit hook or a PR job wants: `--since origin/main` fails on the files in the diff and stays quiet about the mod's existing backlog. The directory is still indexed whole, because the cross-file checks need it — a missing localisation key (CW100) or a bad `filepath` (CW113) is only answerable against every file — but where the ruleset asks for no unused-definition check, which is every HOI4 config today, the files outside the scope are not validated either, so a scoped run does less work than a full one. A ruleset with a `should_be_used` type keeps validating everything and filters the report instead, since CW239/CW231 judge each definition against the references collected from every file. A `--since` ref git cannot resolve fails the run (exit 2) rather than quietly reporting everything or nothing, a `--file` naming nothing on disk is warned about, and combining a scope with `--output-hashes` warns that the baseline it writes covers only the scope. (#110)

- CW240 now offers a did-you-mean quick fix for a misspelled `enum[...]` value, and CW122 can remove unnecessary quotes from a known inline localisation key. The parser records every leaf value's exact source range, so both fixes replace only the value rather than trailing whitespace or a following comment. Cached ASTs rebuild once. (#138)
- A long `workspace/executeCommand` can now be watched and cancelled. A client that passes a `workDoneToken` with `clearAllCaches`, `reindexWorkspace`, `cacheVanilla`, `reloadrulesconfig`, `genlocall` or `fixAllWorkspace` gets the scan's phases reported against that token — "Indexing workspace…", "Indexing base game…", "Building localisation index…", "Validating workspace…", "Publishing diagnostics…" — each with a percentage that keeps moving through the parallel parse and validate passes, so a 30-second reindex on a large mod shows where it is instead of an indeterminate spinner. The server advertises this as `executeCommandProvider.workDoneProgress` so a client can detect it; without a token nothing changes, and the `loadingBar` notification and the server's own `cwtools/scan` stream behave exactly as before. (#223)
- Cancellation is now real rather than advisory. Cancelling rides `window/workDoneProgress/cancel`, a notification the server handles *while* the scan is running; `$/cancelRequest` could not work here, because tower-lsp answers it by dropping the handler future and a dropped future only stops at an `await` — the expensive scan phases are `block_in_place` sections tens of seconds long. The flag is polled per file inside both rayon passes, so a cancelled scan stops within a file instead of at the next phase boundary, and the command returns a result saying so ("Re-index cancelled.") instead of never answering. The one phase that cannot be interrupted mid-flight is the base-game index, a single engine call with no per-file seam; a cancel during it takes effect when it returns. (#223)
- `cwtools validate` reports definitions nothing in the mod uses. A type the config marks `should_be_used = yes` promises every one of its instances is referenced somewhere, and a Stellaris technology promises the same; neither could be checked before, because the answer needs every file at once and the validator only ever saw one. The rule engine now records each `<type>` reference it resolves, the run merges them, and every instance the merged set does not cover is reported as CW239 (`X of type Y is not used anywhere, but is expected to be`) or, for a technology, CW231 (`Technology X is not used`). Technologies the game uses on its own are exempt, matching F#: one that grants a modifier, documents what it unlocks, is weighted out of the draw, or sits behind a feature flag. The whole pass is skipped for a config that marks no type `should_be_used`, which is every HOI4 config today, so HOI4 diagnostics are unchanged. (#93)
- The editor reports CW239/CW231 too. The workspace scan runs the same two-phase pass the batch does and keeps each file's recorded references in a store, so an unused definition gets its squiggle without running the CLI. Editing a reference updates the answer live: adding `uses = my_thing` in one open file clears the CW239 on the open file defining `my_thing`, and deleting the only reference brings it back. A closed file's diagnostic refreshes on the next scan, the same contract missing-localisation (CW100) already has. Costs nothing on a config with no `should_be_used` type, which is every HOI4 config today. (#123)
- Semantic tokens now answer `textDocument/semanticTokens/range` as well as `full`. `full` is the only entry point the server had, so VS Code re-highlighted the whole document after every edit, and each top-level entity in it costs a rule bootstrap (a root descent with subtype merging, the same work the validator does for one entity). The range request runs the same walk with the off-screen entities skipped whole, so a 300-entity file re-resolves what is on screen instead of all of it. `full/delta` stays declined: it needs server-side result caching there is still no invalidation story for. (#84)
- The missing-localisation diagnostic (CW100) now has a quick fix: "Create localisation key". It inserts the missing key right after a sibling key already defined for the same instance, so a new key lands next to the ones it belongs with; if no sibling is defined yet, it appends to an existing loc file for the language, and if the language has no loc file at all, it creates one. It runs for every configured language at once, not just the one open in the editor. (#108)
- A new `fixAllWorkspace` command applies every auto-fixable diagnostic across the whole workspace in a single edit, the multi-file counterpart to a document's "fix all" quick fix (and to `cwtools fix --apply`). CW100's new quick fix is not included, since it has nothing to overlap or batch across a document; `genlocall` already covers generating loc stubs in bulk. (#108)
- Goto-definition works on an enum value. `terrain = forest` used to resolve to nothing, because an enum member has no definition in the game files and goto only knew how to follow a `<type>` reference, a localisation key, a variable and a file path. It now jumps to the member inside the `enum[..]` block that declares it, in the rules folder, landing on the value itself rather than the block header — which is what you want for an enum running to hundreds of values. A complex enum, whose members are collected from the game files instead of listed in the config, lands on its `complex_enum[..]` block, so the hovered value's origin is still one jump away. (#137)
- CW113's "file not found" message claimed the lookup was case-sensitive, but the file index lowercased every path on insert and lookup, so a reference that differed from the on-disk file only by case resolved anyway and the warning never fired on a case-sensitive filesystem. The check now matches every indexed file, mod and base game, by exact on-disk case, so a Windows-authored mod whose `file =` paths only load on Linux/Mac gets the case mismatch flagged. It is on by default; `case-sensitive-files = false` in `cwtools.toml` (or `--case-sensitive-files false`) turns it back off for a mod that must tolerate case mismatches. The base-game cache now stores each path's on-disk case (a cache-format bump, rebuilt automatically) so a cache-restored install is case-checked too. (#140)
- `inline_script` call sites are validated against the body they pull in. HOI4 splices `common/inline_scripts/<name>.txt` in wherever `inline_script = { script = <name> PARAM = value }` appears, replacing every `$PARAM$` with the argument passed; the validator did none of that, so the body went unchecked and the call itself was reported as a block the rules do not know. The named script is now expanded at the call site, substituted, and validated against the rules and scope in force there, counting toward the calling block's cardinality — a required field a script supplies no longer reads as missing. The body's diagnostics keep their own codes and are reported on the call site, each message naming the script line it came from, so a nested call leaves a trail reading innermost first. CW274 covers a call whose body cannot be pulled in at all: an unknown script, a call naming none, a value that is not a block, or a chain that calls itself or nests more than five levels deep. The editor does not load inline scripts yet and accepts a call as written. (#91)
- A broken `.cwt` ruleset is now a reportable diagnostic instead of stderr text. Rules-config problems carry a code and a severity: CW600 for a file or directory the loader could not read, CW601 for a rule naming a type/enum/single_alias nothing defines, CW602 for a `single_alias` expansion it refused, CW603 (a warning) for a `##` directive whose value it could not parse. `cwtools rules` grows `--report-type` (cli, csv, json, github, sarif) and exits 1 when any of them is an error, so CI can fail on a ruleset that would otherwise degrade every check downstream. `validate` carries the same diagnostics at the top of its report, subject to `--ignore-code`, `--only-code`, `--min-severity` and the hash baseline like anything else. The editor gets them too: rules diagnostics in Problems now show their code and their real severity, so `cwtools.errors.ignore` can suppress one. (#130)

- Diagnostics now carry the three extras an editor already knows what to do with. Every `CWxxx` links to its own row in the error-code reference, so the code in the Problems panel is a way into the documentation instead of a number to go and search for; a deprecated construct (CW236) is struck through and a redundant one (CW121, CW231, CW239) faded, so a line you can just delete reads as one before the message does; and the codes that are about two places at once now point at both. CW238 marks the `else`/`else_if` that has no preceding `if`, CW237 the nested `else` that 2.1 rebound, and a CW113 whose path is only wrong by case says which spelling the file is indexed under. `docs/ERROR_CODES.md` gained a stable per-code anchor to link to, and the SARIF report's `helpUri` now lands on the row rather than the top of the file. (#104)

## Bug Fixes

- `validate --since` no longer reports on nothing when the mod directory is spelled differently from the way git resolves it. Git answers `rev-parse` in its own spelling of the repository root, discovery walks the path the run was handed, and the two were compared directly — so a Windows temp dir under an 8.3 short path (`RUNNER~1`), a macOS `/var` path git reports as `/private/var`, or any path carrying a `..` matched nothing and the run said "Discovered 3 files, reporting on 0 of them" while exiting 0. Changed files are now rebuilt under the directory the run was given, so both sides carry the caller's spelling. A changed file outside the mod directory keeps git's spelling, as before. (#266)
- `validate --since` no longer resolves against the wrong repository when it is run from a git hook. Git hands every hook a `GIT_DIR` naming the repo the hook fired in, and that variable outranks the `-C` the scope resolution passes, so a pre-commit or pre-push hook — the case the flag exists for — took its ref, merge base and changed-file list from the hook's repo instead of the mod directory and reported the wrong file set without failing. The hook variables are now cleared for every git call the run makes. The same leak reached the test suite, whose `--since` fixture built its repo with unguarded `git -C <tempdir>` calls: run under the pre-push hook it wrote a test identity into the developer's own git config and committed the fixture over the checked-out branch. (#255)
- The language server now sends `workspace/semanticTokens/refresh` only to clients that advertise support. A client that did not implement the optional request could otherwise leave every workspace scan waiting forever. (#184)
- The localisation languages and the hover settings now apply without restarting the language server. Changing the languages or whether hovers show every language rebuilds the localisation index and diagnostics; toggling debug classification or resolved scopes affects the next hover. (cwtools-vscode#142)
- Cancelling `clearAllCaches` no longer leaves the base-game index dropped. The command purged the caches and cleared the in-memory vanilla state before starting the re-index, so a cancel in between left every base-game reference unresolvable — "not found" on things that exist — until the next background pass rebuilt it. The state is now dropped immediately before the rebuild that replaces it, and a cancel after the purge hands the rebuild to the same bounded background retry `reloadrulesconfig` uses, reporting "re-index cancelled, rebuilding in the background". A cancelled scan also no longer records its walk fingerprint or localisation signature, which a later quiet background pass would otherwise trust and skip work on the strength of. (#223)
- A cancelled scan no longer invents unused-definition diagnostics. Pass 2 rebuilds the `type_uses` store from the files it validated, so stopping partway used to prune every unvalidated file's recorded uses and then report their definitions as CW239/CW231. The rebuild is skipped when the pass was cancelled. (#223)
- The language server now caps the ignore configuration it accepts at both the `initializationOptions` and `workspace/didChangeConfiguration` boundaries. `ignoreFilePatterns` and `ignoreDirectories` keep their first 200 entries, a single glob longer than 1024 characters is dropped, and `ignoredErrorCodes` is capped at 200 entries; everything rejected logs a warning naming the key. A one-megabyte pattern full of `?` used to force roughly 255 million match iterations per file scanned, and the general `*`/`?` matcher no longer runs a pattern-length × filename-length dynamic program at all: it is now a two-pointer scan that is linear in practice and allocates nothing per call, so even a hostile pattern at the cap stays cheap across the whole walk. (#169)
- A localisation value carrying a long run of `[` no longer takes quadratic time to read. A bracket that never closes was retried after advancing a single byte, and every retry scanned to the end of the value before giving up, so one line of 100,000 of them cost roughly five billion byte reads and held up whatever was reading the file: a CLI run, the editor's workspace scan, and the editor again on every keystroke in that file. Brackets that never close are now identified in one pass and taken as the text they are, and a stretch of them costs one text element instead of one per bracket. As a backstop a value over 64 KiB keeps its key, its text and its position but has its `$refs$` and `[commands]` skipped, with a warning naming the key; the longest value in the base game, Millennium Dawn and Kaiserreich is under 8 KiB, so nothing real reaches it. No diagnostics move. (#165)
- The language server now rejects JSON-RPC bodies over 64 MiB before buffering them, caps one open document at 32 MiB, retains at most 128 documents and 128 MiB of source represented by their text and cached syntax trees, and runs at most two live document validations at once. Removing a workspace folder evicts its open documents, and completion requests for unopened documents no longer retain per-URI cancellation state. Completed validation tasks are removed from the debounce registry and a task panic is logged instead of disappearing with its handle. (#164)
- A ruleset whose `single_alias` definitions reference each other no longer costs far more than it describes. Expansion ran to a fixpoint, one level per round, and each round re-copied every shared body once per reference site, so three levels of `n` references materialized `n²` rules and walked `n³` nodes, with the round's cycle check walking all of them again. Definitions are now resolved as a dependency graph: each is expanded once, after everything it references, and substituted as it stands at every site, with its expanded size memoized and charged against a one-million-node budget before anything is cloned. Past the budget, or on a reference cycle, the reference stays a `single_alias_right[...]` (which validates permissively, as an unresolved reference always has) and the loader reports it on the definition it names. The colour, value and ignore passes that follow no longer rescan a shared body once per site either. The HOI4 config spends 2,737 nodes and nests two levels deep, so nothing real comes near the limit and no diagnostics move. (#166)
- The LSP no longer loads rules or reads closed files on a Tokio request worker. Rules loading and closed-file reads are offloaded, and multi-file navigation and workspace fixes batch their reads. `fixAllWorkspace` also refuses stale edits when an open document version or closed-file content has changed, reporting the skipped fixes instead of applying old ranges. (#154, #132)
- A reference written through a subtype-qualified field (`<equipment.naval_equip>`, `<event.country_event>`) now counts toward the unused-definition check. The qualifier was kept verbatim as if it named a type of its own, so the reference matched no declared type, was never recorded, and would have landed in the wrong bucket if it had been: an instance referenced only that way reported CW239 (or CW231 for a Stellaris technology) as unused. Uses are now recorded against the base type, which is what the definition is keyed by. No config in either ruleset marks a type `should_be_used` today and the Stellaris config has no subtype-qualified technology reference, so no diagnostics move. (#139)
- The CW100 "Create localisation key" quick fix and `fixAllWorkspace` can no longer produce an edit that lands outside the workspace. Containment is by canonical path (a base-game install at `mod-vanilla` next to workspace `mod` passed the old lexical prefix check), a candidate file that is a symlink or resolves outside the workspace falls through to the next tier instead of being edited, and the containment is re-derived from the live workspace folders after every folder change. (#160)
- Applying several "Create localisation key" quick fixes for a language that has no loc file yet no longer writes the file's header twice. Each missing key resolved to the same not-yet-created file independently, so a codeAction request returning fixes for more than one missing key at once (an instance missing both `title` and `desc`, say) offered two actions that both created the file and inserted their own header; applying both landed a duplicated `l_<lang>:` header and malformed loc. A later key sharing an earlier one's not-yet-created file now joins that key's action instead of getting its own, so the batch inserts the header once and both stubs. Triggering the fix one at a time, the normal lightbulb flow, was already safe and is unchanged. (#142)
- The language server no longer reads whatever file a client request names. Every per-file URI must be a `file:` URI that resolves to a regular file inside the workspace, the base-game install or the rules directory, and a single read is capped at 64 MiB; anything else is refused quietly (the request answers nothing, and no index state changes). A request naming `file:///dev/zero` previously hung the server reading a device to EOF. An auto-discovered base-game install now counts as readable the same as an explicitly configured one. (#163)
- A file path written in a mod can no longer probe for files outside the search roots. Document links and goto-definition joined a `filepath[..]` value onto the workspace root and the base-game install and stated the result with no containment check, so a value laden with `../` reported whether a file exists anywhere on disk. The join is now contained by canonical path, the same test the file-access boundary uses, and one that resolves outside its root links and jumps to nothing. (#176)
- Cache inputs are now bounded before they are read or decompressed. A `.cwv` base-game cache, a `.cwb` parse-cache entry and its `.cwe` sidecar each have to be a regular file (a path naming `/dev/zero` reported length 0 and then read to EOF), the read itself stops at 128 MiB for a `.cwv` and 64 MiB for a `.cwb`, and a compressed body is refused once it decompresses past 512 MiB or 128 MiB respectively, on the first byte over rather than after the memory is committed. A frame whose header declares an over-cap size is refused without decompressing any of it. Every rejection reads as a cache miss, so the source is re-parsed or the install re-indexed. These paths come from `--vanilla-cache` and the client's `vanillaCache` and `cacheDir`, so a few kilobytes of correctly-prefixed zstd could previously expand until the process died. (#162)
- `clearAllCaches` no longer derives recursive deletion targets from the client-supplied `cacheDir`. Deletion touches only positively identified CWTools cache entries: parse-cache fingerprint directories carrying their `settings.sig` marker and `vanilla-*` caches with the `CWV` header, joined one component at a time under a canonicalized root, with symlinks refused at every level. Pointing `cacheDir` at a directory holding an unrelated `parse-cache/` or `vanilla-*` files leaves them untouched, a cache root that cannot be read reports a failure instead of `Caches cleared (0 files)`, and the result message reports how many files were removed. The same ownership gate now guards the per-scan cache-dir pruning and the settings-change cache clear, which could previously delete through a planted symlink with no command involved. (#159)
- A panic inside the periodic background reindex or a watched-file batch no longer goes dark. Both background tasks now use the startup scan's panic wrapper: the panic is logged, a failed reindex pass does not stop later passes, and a failed batch requeues its events and retries once. A batch that panics twice in a row (a deterministic panic on some file's content) gives up with a distinct log line and leaves its events for the next natural trigger instead of retrying forever. (#155)
- Hovering a base-game event or decision whose title comes from an explicit loc field now shows that title on the cached vanilla path too. The vanilla cache never stored `primary_loc_key`, so the normal fast path fell back to name-derived keys and showed a worse hover than a live scan of the same install. The cache format version is bumped; existing caches rebuild once. (#141)
- A script file that disappears or becomes unreadable after discovery is no longer silently omitted. `discover`, `validate` and `fix` now warn with the path and IO error while continuing over the remaining files. A rules directory that cannot be read now travels through the existing rules-error path instead of loading a partial ruleset without an explanation. (#151)
- The CLI no longer advertises non-emitted diagnostic codes in SARIF `tool.driver.rules`, but `--only-code` still validates pending, non-wired IDs (`CW220`, `CW221`, `CW228`, `CW230`, `CW233`, `CW269`, `CW273`, `CW274`) at parse time. Retired `CW258` is no longer accepted there either. This keeps filters strict while preventing SARIF report metadata from promising diagnostics that cannot fire yet. (#103)

- CW246 ("the variable X has not been set") ran against the variable index for every `value[...]` reference, not just `value[variable]`. Country flags, arrays, division template names, GUI font names and every other named value set were looked up in an index that only ever holds variables, so with the check enabled Millennium Dawn reported 43,646 hits, all but ~60 of them false. It now applies only to the variable namespace. (#92)
- `add_to_array = { array = my_arr value = 1 }` recorded the literal key `array` as a defined variable instead of `my_arr`, and effects that only touch arrays (`resize_array`, `remove_from_array`) were not treated as defining anything at all. Arrays are variables to the engine, so a name defined by an array effect now counts as set, and reading it no longer flags CW246. (#92)
- A built-in variable declared with a scope suffix in `variables.cwt` (`party_popularity@<ideology>`) did not match a read carrying its own suffix (`party_popularity@social_democrat`); only the config side of the `@` was stripped. This was 158 of Kaiserreich's 159 CW246 hits. (#92)
- A variable name built from a scripted effect's `$ARG$` parameters was only skipped when it contained a literal `$$`, so `$TAG$_stability` was checked as if it were the runtime name. (#92)
- A bulk file change landing while a workspace scan was already running made the server retry every half second for the scan's whole duration. An over-cap watched batch collapses into one rescan, but when that rescan lost the in-progress race it requeued its events and immediately re-armed its own window, so at Millennium Dawn scale the log filled with "watched batch over cap" lines for tens of seconds (#90 residual). The losing batch now parks its events and the winning scan drains them once when it finishes, with the loser re-arming itself only when the winner finished in between and its drain came up empty.
- Watched file changes polluted the live localisation overlay, which holds the unsaved keys of open `.yml` files. Every watched event for a loc file treated the whole file as changed and ran the cross-file sweep meant for open-editor edits, up to 200 times per drain window, and the overlay kept an entry per watched file until a delete or a window reload (#90 residual). Watched loc files now get their own overlay, replaced per file on each event and consulted everywhere the open-doc one is, so cross-file references resolve keys added on disk and stop resolving keys removed there. It survives workspace scans on purpose: a scan's index install is built from disk reads that can predate a watched change, and merging into the index instead would lose the keys on the next install. A batch runs one coalesced sweep of the open files instead of one per file, and open documents keep the overlay behavior they had.
- The rules-config error popup could show twice per session, and the details behind it never arrived at boot (#98). The rules load runs once inside `initialize`, where notifications are dropped before the handshake completes, and again when the client fires its boot-time `reloadrulesconfig` after cloning the rules, so the per-error log lines were lost and the popup repeated for the same errors. The popup and the log lines now defer to `initialized` the same way the per-file rule diagnostics already did, and an unchanged error set no longer re-toasts. A genuinely different set, such as after a real rules reload, still does.
- Sixteen more "advice about a key" diagnostics underlined the whole block or statement they sat on instead of the key they complain about, burying however many lines the block spanned under one squiggle (#107 follow-up): CW104/CW105/CW106, CW108/CW109, CW227/CW229, CW236/CW237/CW238, CW247, CW248, CW261 (which underlined an entire entity definition), CW262 (whose did-you-mean fix already edited only the key, so squiggle and edit disagreed), CW267 and CW272. They now mark the key token, the same treatment CW223/CW251/CW253 got in 2.4.0. CW121/CW281/CW280 keep their full-block spans on purpose: their attached fixes delete the whole block.
- `reloadrulesconfig` no longer reports a revalidation it skipped. The client fires it right after the startup scan's loading bar ends, but the bar-off notification goes out before the scan's guard drops, so at boot the command raced the tail of the no-rules startup scan and answered "workspace re-validated" while the stale diagnostics stayed on screen until the next edit. The command now retries until it wins the scan guard (bounded at 60 seconds); if a scan holds the guard the whole time it reports the revalidation as queued, and a bounded background retry lands it once the scan releases. (#193)
- Cancelling `cacheVanilla`, `clearAllCaches`, `reloadrulesconfig` or `reindexWorkspace` while it is indexing no longer leaves the progress indicator running. The server answers a `$/cancelRequest` by dropping the command, which skipped the line that closes the status-bar item and the standard `$/progress` stream, so both stayed live until the window was reloaded. Closing them is now the scanning guard's job, so it also happens when a scan panics, and the scan is released only once the close has gone out — the next re-index can start immediately without its own indicator being closed by the cancelled one. Cancelling stays best-effort: indexing already done is kept rather than rolled back. A close is now sent only when something is actually open, so a `cacheVanilla` that hit a fresh cache no longer emits a stray one. (#204)
- `reindexWorkspace` no longer answers immediately with "Re-index already in progress." when it lands in the same scan-guard gap `reloadrulesconfig` raced (#193). The closing `loadingBar(false)` notification of a scan goes out before its CAS guard drops (`ScanGuard::finish`), so a reindex sent right after the bar-off can lose the CAS and answer without ever sending `loadingBar(true)` — leaving the user with no scan at all. The command now retries until it wins the guard (bounded at 60 seconds, matching `reloadrulesconfig` and `clearAllCaches`); if a scan holds the guard the whole time the command reports "Re-index still pending (another scan is running).". (#220)

- Two commands running at once no longer share one progress bar. Every command with a `workDoneToken` was recorded in a single slot, so starting `cacheVanilla` while a `reindexWorkspace` or `clearAllCaches` scan was still going sent that scan's remaining phases to the newer command's notification; when the newer one finished, the older one's phases fell back to the server's own `cwtools/scan` stream and its bar sat on whatever it had last reported. A scan now reports against the token of the request that started it, so two overlapping operations show two independent bars that each run to completion. (#228)

- A closed or deleted file no longer leaves its auto-fixable problems behind in `fixAllWorkspace`. Every publish is meant to keep that store in step with the Problems panel, but the empty publishes for a deleted file, for a file pruned by a scan because it vanished from disk, and for a closed document all went out raw, so their entries outlived the diagnostics they came from: the command counted them as stale fixes it had skipped, and a document reopened at the version it was closed at could have had the old edit ranges applied to new content. The same close now also rebuilds the file's recorded `<type>` references from what is on disk when the buffer was closed with unsaved changes, so a reference the discard put back stops leaving a false CW239 on the definition it points at until the next full scan. (#133)

## Improvements

- `cwtools validate` now says which checks it could not make. CW113, CW222 and CW500 (and on Stellaris CW227, CW229 and CW250) answer against the union of the mod's definitions and the base game's, so without `--vanilla` or `--vanilla-cache` they report nothing at all — a clean report that was never a clean result. The run prints a line naming them on stderr, whatever the report format, and carries the same text as a `::notice::` in the `github` report and a `toolConfigurationNotifications` entry in the `sarif` one. Nothing changes when a base game is loaded, and no diagnostic moves either way: this is a run-level notice, not a finding, so it stays out of the csv/json rows, the error and warning counts, the hash baseline and the exit code. (#96)
- `workspace/symbol` no longer materializes and sorts every matching symbol in the workspace just to answer with the first 500. The empty query, which the picker sends before you type anything, admitted every type instance, `@`-constant and localisation key, so at Millennium Dawn scale each request cloned and sorted the entire symbol universe. Matches now stream through a bounded top-k heap that rejects a non-improving candidate with one comparison before any string is cloned, and ranking an ASCII name no longer allocates a lowercased copy. The response itself is unchanged: same 500 symbols, same order (a name defined several times in one file now ties by position rather than discovery order). (#136)
- Pull requests no longer wait for the release-profile workspace test suite. Release builds for all three platforms and the full release test suite now run in parallel in the tag-triggered release workflow, and publishing waits for both, so release-only arithmetic coverage and binary checks still gate shipping. (#192)
- `TypeIndex::instances_in_file` and `remove_file` no longer scan a type's whole instance list to find one file's own entries; both now cost proportional to the file, not the type. This is on the hot path for CW100 and the unused-instance check, which run per file on every LSP validate and every CLI run, so a type with thousands of instances spread across many files (state, character, technology) no longer gets rescanned end to end for every file that happens to touch it. The editor paths copy matched rules out constantly (per leaf for semantic tokens, per request for completion and hover) and an `alias[effect:…]` body is one of the largest trees in the ruleset. - The per-block validation walk allocates roughly half as much. Cardinality was the bulk of it: every block built two hash maps and an owned lowercased `String` for each of its rule's keys and each of its children's, whether or not any rule had a cardinality to enforce. Rule keys are ruleset-static and case-insensitive, so a block now carries one small inline card per distinct key, compares against it in place, and skips the whole pass when the rule list has no keyed, bare-value or value-clause rule at all, which is what an effect or trigger body looks like. Reading 512 real corpus files that way drops from 8.95ms to 916µs (-90%), and 64 files from 926µs to 330µs (-64%), measured warm. # 2.4.0

## Bug Fixes

- The "Remove empty if" quick fix deleted valid script. `if = { limit = { tag = GXC } }` followed by an `else_if` was fixed by deleting the `if`, which left the `else_if` with no antecedent for the game to reject. On Kaiserreich, 9 of the 10 places the fix was offered were chain-breaking. It also reached `source.fixAll`, so anyone binding that through `editor.codeActionsOnSave` had files corrupted on save. The fix is now withheld when an `else_if` or `else` follows the block. The diagnostic still reports.
- Diagnostic squiggles ran one line long, and for a block ran to the line past its closing brace. The parser records a node's end as the cursor after the node and the whitespace behind it, which is the start of the next token, and that position was published as-is. It affected all 43 codes that carry a precise range, including the scope errors and type-reference errors modders see most. The published end is now walked back to the last content character. Quick-fix edits are unaffected: they are built from the fix's own range, which still needs to absorb the trailing newline to delete a line cleanly.
- Hints about a single keyword underlined the entire block that keyword opened, burying however many lines the block spanned under one squiggle. CW223 (`NOT` with multiple children) now marks the `NOT`, CW251 (unnecessary `AND`/`OR`) marks the operator, and CW253 (deprecated `set_empire_name`) marks the key, which is the same span its rename fix already edited. This is old behavior that only became visible in the last release, when the server started publishing the ranges it had been recording all along.
- Nothing under `localisation_synced/` got any language features, and none of the keys defined there were indexed, so script referencing them read as missing. HOI4 ships synced localisation in that directory and the client has always treated it as localisation. The loc walker and the server's own check now agree with it.
- The "N rules-config error(s)" popup pointed at an output channel that never had the errors in it. The details were written to the language client's channel ("Paradox Language Server"), not the extension's ("CWTools"), and the per-file diagnostics meant as the fallback were published during `initialize`, where notifications are dropped before the handshake completes. The popup now names the first error inline, and the diagnostics are held until `initialized`.
- Diagnostic hashes were keyed on whatever path string an invocation happened to produce. Both `--directory` and a `cwtools.toml` yield an absolute path, but they build it differently: the flag is taken verbatim, while a config anchors on the process's current directory, which the OS reports with symlinks already resolved. On macOS that turns a temp path into `/private/var/...` on one route and leaves it `/var/...` on the other. The same mod validated two equivalent ways could produce two different baselines, which is why `validate --output-hashes` was unstable across macOS and Windows CI runs even though the same mod and rules were in play. The hash is now computed from the file path relative to the resolved mod root, `/`-separated regardless of host, falling back to the old path string for a file that genuinely sits outside the root (a vanilla install path, say) rather than panicking.

## Notes

- **Behavioral:** CW223, CW251 and CW253 cover their keyword rather than the block they open. Anything matching on diagnostic ranges rather than the start position will see the change.
- **Behavioral:** `localisation_synced/` is now walked for localisation. Keys defined there join the index, which clears missing-key errors against them and can surface duplicate-key errors that were previously hidden by the directory being skipped.
- **Behavioral:** diagnostic hashes are now relative to the mod root instead of the raw path string that produced them, so every existing `--ignore-hashes` baseline needs re-blessing (rerun with `--output-hashes` and commit the result). `legacy_diag_hash` still matches baselines written before this release during the migration window; only the new digest is ever emitted.

# 2.3.0

## Features

- The entity graph works. The VS Code extension has shipped a full graph visualiser for a long time, but the `getGraphData` command it calls was never implemented on the Rust side, so the whole feature sat greyed out. The server now answers it: a breadth-first walk out from the requested entity type, bounded by the requested depth, built from the same reference data that backs find-references. Nodes are capped at 500 (half the budget reserved for seeds, so a truncated graph is a connected neighbourhood rather than an alphabetical slice) and truncation is reported in the node details. A `## graph_related_types` list on a type restricts which types may join the walk; an empty list, which is what the HOI4 config writes, means no restriction.
- Semantic tokens (`textDocument/semanticTokens/full`). In a language where nearly every line is `key = value`, a TextMate grammar alone cannot tell a type reference from an enum member from a localisation key. The server already resolved all of that for hover and goto, and now hands the same classification to the editor: keys, operators, numbers, booleans, comments, type references, enum members, scope names, script variables, and alias-resolved effect and trigger keys, with a `declaration` modifier on a key that declares a type instance.
- Colour swatches and a native colour picker on colour fields (`textDocument/documentColor`, `textDocument/colorPresentation`). Both spellings round-trip in the convention they were written in, so the picker does not rewrite `{ 51 102 153 }` into floats or vice versa. Recognises RGB floats, RGB integers, an explicit `rgb` prefix, `hsv`, and `hsv360`.
- A `source.fixAll` code action applies every fixable diagnostic in a document at once, so `editor.codeActionsOnSave` can be bound to it. Overlapping edits are skipped rather than corrupting each other, using the same planner the `fix` subcommand uses.
- The server reports scan progress through standard `$/progress` as well as the custom `loadingBar` notification it has always sent. `cwtools-server` runs standalone, so in Neovim, Helix or Zed the initial index previously looked like a hang. `workspace/didChangeWorkspaceFolders` is now advertised and handled (it re-points the primary folder and rescans; indexing several roots at once is still not supported).
- `cwtools.toml`, discovered by walking up from the mod root, or named explicitly with `--config`. It covers game, rules, vanilla, cache behaviour, ignore globs, loc languages, severity and code suppression, so a CI job collapses to `cwtools validate`. Command-line flags override file values, relative paths resolve against the config file's own location, and a key the running subcommand does not read is named in a warning instead of silently ignored.
- `--report-type github` emits GitHub Actions workflow commands, which put diagnostics straight onto the pull request diff. `--report-type sarif` emits SARIF 2.1.0 with a rules array generated from the error-code catalog.
- `--ignore-code` and `--only-code` on `validate` and `loc`, both repeatable and validated against the known code list, so an editor and a CI job can share one suppression policy instead of falling back to hash baselines.
- `cwtools --version`. It existed on `cwtools-server` and not on the CLI.
- `cwtools parse` prints the parse errors it finds and exits non-zero, instead of printing a summary and reporting success on plainly malformed input.
- `validate --vanilla` and `fix --vanilla` now build and reuse a base-game index cache the way the language server already did, cutting a warm run's load time by about a third and its peak memory by about 40%. `--no-vanilla-cache` bypasses it and `--refresh-vanilla-cache` forces a rebuild.
- `--loc-language` filters localisation at parse time rather than after the fact, so unselected languages are never materialised.

## Bug Fixes

- A single `'` inside a localisation command crashed the process. `[GetName(')]` satisfied both the opening and closing quote test with one character, producing a reversed slice. Since localisation parsing runs across rayon with nothing catching panics, a two-line `.yml` file was enough to take down `cwtools loc`, `cwtools validate`, and the language server.
- Deeply nested clauses overflowed the stack and aborted the process. There was no depth limit, and a stack overflow aborts rather than unwinds, so nothing could catch it. A 48 KB file was enough to kill the language server, whose tokio workers get 2 MB stacks, and because the file stays on disk it aborted again on every restart. Clause nesting is now capped at 256, which is over ten times the deepest nesting measured across Kaiserreich, HOI4 vanilla and the rule config, and well under the depth at which validation itself runs out of stack. Past the cap the subtree is skipped with an error and the rest of the file still parses.
- The structural checks only recognised one spelling of each operator. They compared case-preserving interned ids, so `IF = { }` skipped the empty-if check that `if = { }` triggers, and `not = { a b }` skipped the NOR warning that `NOT = { a b }` triggers. Paradox script is case-insensitive here, so those spellings are valid script that silently skipped validation. They now compare case-folded. A lowercase `or` also used to fall through to a branch that produced a false "unnecessary AND" warning; that is gone.
- Related to the above: `and`, `or` and `not` are also arithmetic operators inside dynamic-value blocks, where they are not boolean logic. A block with a direct `value =` child is now treated as arithmetic and skips the boolean checks, which is what keeps the case fix from reporting ten false positives on Kaiserreich.
- A localisation file headed `L_English:` instead of `l_english:` had its language resolved as unknown, which dropped every key in the file out of the index and cascaded false missing-key errors across the mod. The header check is now case-insensitive, matching the two sibling checks that already were.
- `validate` reported success when it had validated nothing. A `--rules` directory that existed but held no rule files loaded zero types and exited 0, and a `--directory` that did not exist discovered zero files and exited 0, so a CI job with a typo'd path was permanently green. Both now fail loudly, naming the input and its resolved path. See the exit code note below.
- `cwtools validate` reported a missing-localisation error for every key when a mod had no `localisation/` directory at all. The language server already guarded this; the batch pipeline did not.
- Published diagnostic ranges used raw character columns instead of the position encoding negotiated with the client. On any line containing a non-BMP character, the quick fix attached to a diagnostic applied at different columns than the diagnostic itself, which corrupted the line it was meant to repair.
- A `$variable$` reference could be clean in CI and after a workspace scan, then report an unresolved-reference error the moment the file was opened, then clear again on the next rescan. The per-keystroke path built its set of valid references from a strict subset of what the other two paths used.
- A `.yml` file outside any `localisation/` directory was validated as a localisation file, so opening something like `.github/workflows/ci.yml` reported missing-language-header errors on it. The check now requires the directory as well as the extension.
- A corrupted `.cwb` cache could be served as a valid parse tree. The payload carried no integrity check, and structural validation does not catch content corruption, so of 507 single-bit flips tested, 66 decoded into a different abstract syntax tree and were used without complaint. Cache payloads now carry a frame checksum. Existing cache files still load, so no rebuild is needed.

## Notes

- **Behavioral:** `validate`, `loc` and `fix` now exit 3 when the target directory does not exist, and exit 4 when the ruleset loaded no types or the target yielded no files. Both previously exited 0. Pass `--allow-empty` to restore the old behaviour for the empty cases; a nonexistent directory is always an error.
- **Behavioral:** diagnostic hashes used for `--ignore-hashes` baselines are derived from the source line's content instead of its line number, so inserting a line above a diagnostic no longer invalidates its baseline entry. Existing baselines still match for this release, but only the new digest is emitted, so rewriting a baseline converts it. The `hash` column in csv and json output changes accordingly.
- **Behavioral:** `--vanilla` runs now write a base-game cache under the OS cache directory (`XDG_CACHE_HOME/cwtools`, `%LOCALAPPDATA%\cwtools`, or `~/.cache/cwtools`), about 20 MB per game version and rule config. The path is printed on both a hit and a write. The cached path is not a byte-for-byte substitute for the live walk: it carries vanilla complex-enum and value-set members the live walk dropped, and does not carry parsed vanilla localisation command chains.
- **Behavioral:** `--loc-language` now scopes which localisation files are parsed, so a key defined only in an unselected language no longer satisfies an existence check. Previously the key union spanned every language regardless of the flag.
- **Behavioral:** the structural checks now fire on every casing of `if`, `limit`, `not`, `and`, `or` and `nor`. Kaiserreich output is unchanged, but a codebase using lowercase boolean operators outside a math block will see new diagnostics. They are true positives.
- The minimum supported Rust version is now declared as 1.88.0 and enforced per crate. It is bound by let-chains in this codebase, not by any dependency. A CI job builds at exactly that version so it cannot drift upward unnoticed.

## Developer

- The string interner is sharded across 64 locks keyed on the case-folded bytes, replacing a single process-wide write lock. Parsing used to anti-scale, so the validator was faster on 6 threads than on 24. It is now faster on 24 than on 6, and a full Kaiserreich run with vanilla went from 5.25s and 1529 MB to 1.46s and 935 MB, with byte-identical output. The shard is chosen from the folded bytes so every casing of a string keeps one home, which is what lets the case-folded id stay canonical. `PartialOrd` and `Ord` were removed from the string id to make any future ordering assumption a compile error.
- Localisation completion no longer sweeps the whole key union per keystroke. A sorted blob with a per-key character mask, built once per scan, answers a request in about 140 microseconds against 400,000 keys where the linear sweep took 20 milliseconds.
- `scripts/corpus-guard.sh` makes the regression corpus a runnable, committed gate instead of a command re-typed from a plan document. It drops `--vanilla` deliberately: the guard needs determinism, not vanilla coverage, and without it the inputs are two public repositories pinnable by commit. Paths are overridable, drift prints a per-code summary and a full diff, and `--bless` re-blesses after an intentional change.
- Fuzz targets for the script parser and the localisation parser under `cwtools-rs/fuzz/`, seeded from `testfiles/` plus the two crash inputs fixed in this release. The fuzz crate is excluded from the workspace. CI replays the seed corpus on every pull request rather than running a campaign, so a failure is always reproducible from the pull request alone.

- A release build that produced one binary but not the other used to be archived quietly and still satisfy the artifact check. A missing expected binary now fails the release.
- The cache crate's format version and corruption handling are tested for the first time across two format bumps: wrong version byte, truncated file, zero-byte file, and bit-flipped payload.
- `crates/rules/tests/load_ruleset_dir.rs` was a false green. It printed "skipping" and returned when the rule config was absent, so in CI the only test that loads a real ruleset passed while asserting nothing. It is split into a fixture-backed test that always runs and an ignored test that hard-fails when the config it needs is missing.

# 1.25.0

## Bug Fixes

- Closing a file that had unsaved edits no longer breaks navigation to the symbols it defines. `did_close` used to drop the file from the index until the next full rescan, so go-to-definition and find-references across the workspace stopped resolving anything the closed file declared. # Pre-1.19.0: completion responsiveness and ordering

## Improvements

- A variable carrying a null-coalescing default selector (`my_var?150`) lexes as one key instead of splitting at the `?`; the `my_var?150 = { ... }` and `my_var?150 = 100` forms are no longer reported as an unexpected value plus an orphan block (CW264/CW265)
- A character created by `generate_character` (`token_base = ...`) can be used as a scope (`<token> = { ... }`) instead of being flagged (CW262); value-sets defined in mod files are now collected (previously vanilla-only) and read from the field the rule actually binds rather than a fixed key guess
- Loop effects (`for_each_loop` and friends) seed their implicit `v`/`i`/`break` temp variables, and any explicitly named `value`/`index`/`break`, so the body can read them without being flagged as unset (CW246)

## Changed

- Hover shows ROOT, PREV, FROM, and FROM.FROM next to the current scope, restoring the scope table

## Developer

- The language server warns when the rules directory it is given does not exist, mirroring the vanilla-dir check, which helps diagnose an unresolved Windows `rules_folder`

# 1.6.0

## Bug Fixes

- Stellaris if/else and event checks now detect mixed-case keys (e.g. `IF`, `Trigger`, `Mean_Time_To_Happen`); the ambiguous-if/else and every-tick-event checks (CW236/CW237/CW238/CW107) were silently skipped whenever a key wasn't already lowercase
- Hover, go-to-definition, and completion treat `.yaml` and `.csv` localisation files the same as `.yml`; previously hover and go-to-definition only recognised `.yml`, so `$KEY$` resolution silently skipped the other two
- `.mod` descriptor values with a trailing comment or a quoted `=` parse correctly (e.g. `replace_path = "common/ideas" # keep`); the old parser left the closing quote attached, so the directory failed to override vanilla
- While typing, diagnostics already computed for open dependent files are published instead of discarded when a newer edit arrives mid-pass
- Two game installs that can't be fingerprinted (no launcher file, unreadable mtime) no longer share one vanilla-cache key; the install path is hashed in as a tiebreaker

## Performance

- Glob matching (file include/exclude, run for every file and directory) uses a single rolling DP row instead of allocating an (m+1)x(n+1) grid per match
- Validation error codes are stored as `&'static` references instead of allocating a `String` per finding
- LSP: a burst of keystrokes coalesces to one pending validation task per file instead of stacking a debounced task per keystroke, the shared modifier-key set is snapshotted by refcount instead of deep-copied per scan, and the per-document token lock is no longer held across the full arena walk that rebuilds the set
- Scope resolution (run per command token during validation) is ~49% faster: the per-token lowercase, scope-stack copy, and subscope check no longer allocate
- Parsing is ~32% faster: tokens intern slices of the source directly instead of building a throwaway `String` first, and the character-class checks use a lookup table
- Localisation parsing is ~14% faster: streaming line and element parsing with borrowed text runs instead of an allocation per entry
- Rule validation does fewer per-leaf and per-block allocations: candidate matching, alias and scope-key lookups, cardinality counting, and subtype selection lowercase lazily, reuse scratch buffers, and use O(1) alias/type-instance maps
- The workspace index avoids per-leaf string allocations via thread-local lowercase buffers, borrowed value lookups, and a one-pass type-instance map
- LSP requests reuse work instead of rebuilding it: parallel first-pass scanning, memoised scope and enum completions, a refcounted workspace URI, in-place document updates, and async file-existence checks off the request path
- Loading a cached file interns its strings in one locked batch instead of taking the interner lock per string

## Changed

- The CLI exits with distinct codes so CI can tell an operational failure from validation findings: 3 = file discovery failed, 2 = report write failed, 1 = validation found errors, 0 = clean. Previously all three returned 1

## Developer

- A `.cwt` link that lists an unknown input scope is now logged (naming the link and the bad scope) instead of being silently treated as any-scope
- Filesystem read errors during index building are logged instead of silently producing an incomplete index, and `write_cache` propagates a `create_dir_all` failure instead of swallowing it
- Added a criterion benchmark harness for hot-path functions (glob matching, scope resolution, parsing, string interning, localisation parsing)
- Added a code-review findings spec mapping the reviewed issues to the 1.6/1.7/1.8 releases
- Collapsed the duplicate `JominiCommand`/`JominiParam` types into one: the localisation parser stores command chains directly instead of converting between near-identical types and dropping nested parameters (validation output unchanged)

# 1.5.0

## Bug Fixes

- Order of battle references (`load_oob`, `oob`, `set_naval_oob`, `set_air_oob`) resolve on the Windows build again; the file under `history/units` is found instead of reporting CW500
- `NOT = { AND = { ... } }` is no longer flagged as an unnecessary AND (CW251); HOI4 `NOT` acts as NOR, so the AND is a meaningful NAND, not redundant
- An `AND` inside a `count_triggers` block is no longer flagged as unnecessary (CW251); each direct child is a separately counted condition, so the AND groups several into one counted unit
- A localisation-field value that embeds an inline `[...]` command with a literal prefix/suffix (e.g. a `meta_effect` variable `"[?ROOT...GetTokenKey]_subtype"`) is no longer flagged as an undefined loc key (CW100); it resolves at runtime
- Built-in game variables used without the `var:` prefix (e.g. `faction_leader`) are no longer flagged as unset variables (CW246)
- Event and news pictures set through scripted localisation (`picture = "[SomeFunction]"`) are no longer flagged as an unknown sprite (CW500)
- Localisation `$...$` references to dynamic modifiers, game-object names, and script variables no longer flag as undefined (CW225); genuine typos still do
- Filepath references with a redundant double slash (e.g. `gfx//interface/...`) resolve as the engine treats them instead of reporting CW113
- Windows: trigger/effect documentation (`###`) tooltips, go-to-definition, and validation now work for files whose paths use backslash separators

## Changed

- Hover tooltips show the current scope at the cursor
- Hover and Ctrl+Click work on nested `$KEY$` references inside localisation .yml files: hover shows the referenced entry's text, Ctrl+Click jumps to it
- A broken rules config is flagged: a `.cwt` rule referencing an undefined type, enum, or single_alias reports an error on the offending line
- Autocompleting a plain field inserts `name =` with the cursor after the `=`, instead of just `name`
- Autocompletion on a fresh line after a field offers the block's fields again, instead of the editor falling back to plain word suggestions (most visible in shared_focus / focus files)
- Objects whose type declares `## required` localisation are flagged when that loc key is missing (CW100), so missing localisation is visible again

## Developer

- Normalised Windows path separators across type resolution, the file index, and logical-path derivation so editor features hold up on the Windows build
- The LSP workspace scan walks files in a deterministic, sorted order independent of the filesystem's directory order
- Added regression tests for CRLF `###` docs, scoped hover, `$KEY$` navigation, scripted-loc references, NOT/AND structural checks, count_triggers AND, embedded `[...]` loc commands, built-in variables, backslash path resolution, blank-line completion, and missing-localisation
- `cwtools_index` no longer declares an unused `serde` dependency; `cargo machete` is clean

# 1.0.3

## Bug Fixes

- Ctrl+Click (go-to-definition) now resolves character, focus, idea, scripted_effect, oob, localisation key, and special_project references, including quoted values and sp:-prefixed scope links
- Localisation key go-to-definition jumps to the English (primary) entry instead of whichever language loaded first
- Cross-file references (e.g. scripted effects) no longer show transient "not found" errors before the workspace finishes indexing; opening a definition file now re-validates the open files that use it
- Autocomplete now works in localisation .yml files
- `if` without a `limit` is flagged as an error again, and an empty `limit = { }` now warns (CW281)

## Changed

- Hover tooltips show only localisation, description, and required scopes by default; the raw field/type classification moved behind the new `cwtools.hover.debug` setting (off by default)
- Ctrl+Click opens the definition in a peek by default for cwtools files; set `editor.definitionLinkOpensInPeek` to false to jump straight to it
- Diagnostics now wait until the initial workspace index finishes, so references aren't briefly flagged as undefined on startup
- Rules-config parse errors are surfaced in the editor (a popup, the CWTools output channel, and a diagnostic on the offending .cwt line) instead of being logged silently
